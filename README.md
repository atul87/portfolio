### 5. 🛡️ Production Security & Spam Protection
- **Honeypot Trap:** Hidden field (`#contact-website`) intercepts automated bots silently with zero server resource leakage.
- **Input Sanitization & Escaping:** Regex email validation, payload type checks, and HTML entity escaping prevent XSS and injection attacks.
- **HTTP Security Headers:** Configured in `next.config.js`:
  - `X-Frame-Options: DENY` (Clickjacking protection)
  - `X-Content-Type-Options: nosniff` (MIME sniffing prevention)
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`

## ⚡ Quick Start & Local Setup

### Prerequisites
- **Node.js:** v18.17.0 or higher
- **Package Manager:** npm (v9+) or pnpm

### 1. Clone & Install
```bash
git clone https://github.com/atul87/portfolio.git
cd portfolio
npm install
```

### 2. Configure Environment Variables
Create a `.env.local` file in the root directory:
```env
# Contact Form Email Delivery (Gmail App Password)
EMAIL_ADDRESS=your_email@gmail.com
GMAIL_PASSKEY=your_16_digit_app_password

# Optional: Telegram Notification Bot
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id

# Optional: Upstash Redis for Distributed Rate Limiting
UPSTASH_REDIS_REST_URL=your_upstash_redis_url
UPSTASH_REDIS_REST_TOKEN=your_upstash_redis_token

# Site Canonical URL
NEXT_PUBLIC_APP_URL=https://portfolio-five-black-83.vercel.app
```

**Vercel production setup:** The production `EMAIL_ADDRESS` is configured as `atulverma15704@gmail.com`. In Vercel **Settings → Environment Variables**, add `GMAIL_PASSKEY` with the **Production** environment selected. Use a Gmail App Password, not your normal account password. Save it and redeploy. Keep credentials in Vercel's environment-variable settings; never commit them to Git or paste them into chat. Telegram variables are optional.


### 3. Run Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) to view the application in your browser.

### 4. Build for Production
```bash
npm run build
npm run start
```

## 🧪 Automated Testing Suite

The repository is equipped with an end-to-end test suite powered by [Playwright](https://playwright.dev/):

```bash
# Run all end-to-end tests across headless Chromium
npm run test:e2e

# Run tests in interactive UI mode
npx playwright test --ui

# Run linter checks
npm run lint
```

### Test Coverage Highlights
- ✅ **API Health & Validation:** Verifies status codes, JSON format enforcement, spam honeypot trap, and rate limiting.
- ✅ **Assets & Resume Integrity:** Validates that `/resume.pdf` exists and returns a valid `%PDF` binary header.
- ✅ **Projects & Micro-interactions:** Tests category filters, project-card link rendering, and copy actions.
- ✅ **Research & DOI Links:** Checks that the configured IEEE ISCS and SCEECS DOI links are present.
- ✅ **SEO & Metadata:** Asserts dynamic sitemap generation, crawler robots rules, OpenGraph preview images, and canonical links.
- ✅ **Accessibility & Mobile UX:** Verifies keyboard Escape key drawer collapse and screen-reader compliant aria tags.
